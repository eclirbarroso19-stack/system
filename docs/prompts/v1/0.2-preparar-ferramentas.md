## Dia 1: Git e GitHub (~40 min)

### 1. Abrir o terminal na pasta certa

1. Abra o **VS Code**.
2. Vá em **Arquivo → Abrir Pasta** e escolha `C:\Users\Lenovo\Desktop\project\system`.
3. Abra o terminal com **Terminal → Novo Terminal** (ou `Ctrl + '`).
4. Confira se o caminho no terminal termina em `\system`.

### 2. Conferir as ferramentas

Digite um comando por vez e aperte Enter:

```powershell
git --version
node -v
```

Os dois precisam mostrar um número de versão. O `node -v` deve mostrar `v26.13.1`.

O Claude Code você usa pela **extensão do VS Code** (o ícone ✳ na barra), como já faz nos outros projetos. Não precisa do comando `claude` no terminal.

### 3. Dizer ao Git quem você é (só uma vez na vida)

**Privacidade:** o repositório é público, e o e-mail do `git config` aparece em cada commit. Use o e-mail "escondido" que o GitHub oferece:

1. No GitHub, clique na sua foto → **Settings → Emails**.
2. Marque **"Keep my email addresses private"**.
3. Copie o e-mail que aparece, no formato `12345678+eclirbarroso19-stack@users.noreply.github.com`.

Depois, no terminal, troque o e-mail pelo que você copiou:

```powershell
git config --global user.name "Eclir Barroso"
git config --global user.email "COLE-AQUI-O-EMAIL-NOREPLY"
git config --global init.defaultBranch main
```

### 4. Criar o repositório no GitHub

1. Entre em https://github.com/new.
2. **Repository name:** `system`.
3. Marque **Public**.
4. **Não** marque "Add a README", nem .gitignore, nem license. A pasta já tem tudo.
5. Clique em **Create repository**. Deixe essa página aberta.

### 5. Ligar as permissões do Claude Code

O arquivo de permissões já está pronto, mas precisa ir para uma pasta escondida chamada `.claude`. No terminal, dentro da pasta `system`:

```powershell
mkdir .claude
copy docs\prompts\v1\settings-claude.json .claude\settings.json
```

Se aparecer que a pasta `.claude` já existe, rode só a segunda linha.

✅ **Fim do dia 1.**

## Dia 2: Claude Code prepara a pasta + primeiro envio (~60 min)

### 6. Prompt A (cole no Claude Code)

Com a pasta `system` aberta no VS Code, abra a extensão do **Claude Code** (ícone ✳), clique em **nova conversa** e cole:

```
Execute a etapa 0.2 do SYSTEM. Leia CLAUDE.md e docs/prompts/PAINEL.md e siga a seção "Especificação para o Claude Code" de docs/prompts/v1/0.2-preparar-ferramentas.md. Trabalhe sem fazer perguntas. No fim, me dê o resumo para testar.
```

### 7. Primeiro envio para o GitHub (você faz, no terminal)

Quando o Claude Code terminar, abra o terminal do VS Code (`Ctrl + '`) e digite:

```powershell
git remote add origin https://github.com/eclirbarroso19-stack/system.git
git push -u origin main
```

- Vai abrir uma janela do **Git Credential Manager** pedindo login no GitHub.
- Escolha **"Sign in with your browser"** e autorize.
- Isso acontece **só uma vez**. Depois o Claude Code consegue fazer `git push` sozinho.

Se aparecer `remote origin already exists`, tudo bem: o Claude Code já criou. Rode só o `git push -u origin main`.

### 8. Ligar o GitHub Pages

1. No GitHub, abra o repositório `system` → **Settings → Pages**.
2. Em **Source**, escolha **Deploy from a branch**.
3. Em **Branch**, escolha `main` e a pasta `/ (root)`, e clique em **Save**.
4. Espere 1 a 2 minutos e atualize a página. Vai aparecer: "Your site is live at https://eclirbarroso19-stack.github.io/system/".

✅ **Fim do dia 2.**

## Se travar

| Problema | Solução |
|---|---|
| `git` ou `node` "não é reconhecido" | Feche e abra o VS Code. Se continuar, reinstale marcando "Add to PATH" |
| O push pede senha no terminal | O GitHub não aceita a senha da conta ali. Rode `git config --global credential.helper manager` e tente de novo |
| Erro `rejected` no push | O repositório não estava vazio (criado com README). Traga o erro para o Claude no projeto |
| O Pages mostra 404 | Espere 5 minutos. Confira se existe um `index.html` na raiz do repositório |
| O Claude Code pede permissão o tempo todo | Confira se `.claude\settings.json` existe (passo 5). Ao perguntar, escolha "Yes, don't ask again" |

## Especificação para o Claude Code

> Esta parte é para o Claude Code. O Eclir não precisa ler.

1. **Conferir a pasta.** Precisam existir `docs/`, `design/`, `CLAUDE.md`, `.gitignore` e `.claude/settings.json`. Não apague nem mova nada disso.
2. **Iniciar o Git**, se ainda não existir: `git init`, com a branch `main`.
3. **Criar o `package.json`** com exatamente isto (sem dependências):
   ```json
   { "name": "system", "private": true, "type": "module", "scripts": { "test": "node tests/rodar.mjs" } }
   ```
4. **Criar uma página de teste** temporária em `index.html` (será substituída na etapa 1.1):
   - fundo `#0A0A12`;
   - o logo de `design/logo-system.svg` centralizado, com caminho relativo `./design/logo-system.svg`;
   - o título `SYSTEM: PORTAL EM CONSTRUÇÃO` em azul neon `#00D4FF`;
   - a data de hoje no formato DD/MM/AAAA, calculada com a hora local do navegador;
   - fonte do sistema (as fontes locais chegam na 1.1).
5. **Criar o teste mínimo** de `dia.js`, para já deixar a rede de segurança armada:
   - `js/nucleo/dia.js` exporta:
     - `diaDoJogo(data = new Date())`: devolve `"AAAA-MM-DD"` usando `getFullYear/getMonth/getDate` de `new Date(data.getTime() - 4h)`. **Nunca** `toISOString()`.
     - `horasAteVirada(data)`: horas inteiras, arredondadas para cima, até as próximas 4h.
   - `tests/testes.js` exporta um array `[{ nome, rodar() }]` em que `rodar` lança erro se falhar. Inclua testes de:
     - 03:59 de terça conta como segunda;
     - 04:00 de terça conta como terça;
     - 23:30 conta como o mesmo dia;
     - 21:00 → `horasAteVirada` = 7.
   - `tests/rodar.mjs` importa os testes, roda tudo e imprime `✔ nome` / `✘ nome: erro` e o total. Encerra com código 1 se algo falhar.
   - `tests.html` roda os mesmos testes no navegador e mostra a lista em verde ou vermelho, com o visual neon.
   - Rode `node tests/rodar.mjs`. Tudo tem que passar.
6. **Conferir o `.gitignore`.** Precisa bloquear `system-backup-*.json`, `*backup*.json` e planilhas. Ele **não** pode bloquear `package.json`, `.claude/settings.json` nem `manifest.webmanifest`.
7. **Primeiro commit:**
   - rode `git add -A` e depois `git status`;
   - confira que nenhum backup, planilha ou arquivo pessoal entrou;
   - commit com a mensagem `etapa 0.2: estrutura inicial, página de teste e testes do dia`.
8. **Não faça `git push`** nesta etapa. O primeiro push é do Eclir, porque precisa de login.
   - Se ainda não houver remote, rode `git remote add origin https://github.com/eclirbarroso19-stack/system.git`.
9. **Atualizar o PAINEL:**
   - 0.1 = ✅ e 0.2 = 🔄, com a nota "falta o push e o Pages, feitos pelo Eclir";
   - próximo passo = "Eclir: fazer o primeiro push (passo 7), ligar o Pages (passo 8) e testar no celular. Depois, etapa 1.1";
   - atualize `painel-dados.js` igual;
   - registre no Diário de Bordo.
   - Faça commit.
10. **Resumo final para o Eclir**, em português simples: o que foi criado e os comandos exatos dos passos 7 e 8.

> **Quando o Eclir confirmar que o Pages abriu:** o próximo prompt (a etapa 1.1) começa marcando 0.2 = ✅.
